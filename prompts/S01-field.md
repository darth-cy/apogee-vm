# S01 — Fr Field (with Montgomery) + Constants Skeleton

## Deliver
- `crates/field` holds `Fr`, the BN254 scalar field.
- `crates/constants` is a skeleton crate with zero logic and only frozen constant definitions. It defines the Fr modulus limbs, Montgomery R and R², the modulus inverse, a `PROTOCOL_VERSION` placeholder, and an empty `transcript_tags` module.
- You create the workspace `Cargo.toml`, a per-crate `CLAUDE.md`, and a `docs/` skeleton holding an empty `handoff/` and `GLOSSARY.md`.

The public API below is frozen. Its semantics are exact; naming of internals is flexible.

```rust
pub struct Fr(/* 4 x u64 Montgomery limbs, private */);
impl Fr {
    pub const ZERO: Fr;  pub const ONE: Fr;
    pub const MINUS_ONE: Fr;  // (S11 uses it as the decoded-table padding sentinel)
    pub fn from_u64(x: u64) -> Fr;
    pub fn square(&self) -> Fr;
    pub fn pow(&self, exp: &[u64; 4]) -> Fr;
    pub fn inverse(&self) -> Option<Fr>;          // None for zero
    pub fn to_bytes(&self) -> [u8; 32];           // canonical LE, per master rule 3
    pub fn from_bytes(b: &[u8; 32]) -> Option<Fr>; // None if >= modulus
}
pub fn batch_inverse(xs: &mut [Fr]);              // zero entries stay zero
// plus Add/Sub/Mul/Neg operator impls (owned and by-ref), PartialEq/Eq, Debug printing canonical hex
```

## Core algorithm
Arithmetic runs in Montgomery form over 4×u64 limbs. Multiplication is CIOS Montgomery multiplication with `u128` limb-product intermediates. Inversion is Fermat's little theorem: `pow(p-2)` through the frozen `pow`. `batch_inverse` is Montgomery's trick, skipping zeros so that zero maps to zero. Serde crosses the Montgomery boundary, so the bytes are always canonical non-Montgomery LE. `serde` impls routed through `to_bytes` and `from_bytes`, and the `*Assign` operator forms.

## Must-be-exact
1. The modulus is exactly the master's frozen invariant: Fr, not Fq. Do not swap them.
2. `Fr` is a concrete struct, and no `F: Field` trait generics appear anywhere.
3. Montgomery form never escapes memory. `to_bytes` and `from_bytes` are the only wire path, and both are canonical LE.
4. `from_bytes` rejects non-canonical input, meaning a value ≥ modulus, with `None`. It never silently reduces.
5. `batch_inverse` handles zeros exactly as specified above.
6. `constants` contains no logic. It holds constant items and doc comments, nothing else.
7. Reference libraries (arkworks-bn254) appear only as dev-dependencies or fixture generators.
8. `crates/constants` is `#![no_std]`, holds constant data only, and stays that way forever, because guest-side code links it. `crates/field` is likewise `#![no_std]`, core arithmetic only.
9. `Fr` derives `Copy` and `Clone`.
10. `crates/field` implements its arithmetic in portable stable Rust with `u128` intermediates: no carry intrinsics, no inline assembly, no nightly features. It therefore compiles unchanged for the guest target.

## Acceptance
1. The KAT file `crates/field/tests/vectors/fr_kats.json` (or similar committed format) holds ≥ 50 vectors for add/sub/mul/square/inverse/pow, generated by an arkworks-bn254 fixture generator (dev-dependency or `tools/` generator) and committed to the repo, pinned by content. Tests read the file and never inline literals.
2. A differential test runs 1,000 randomized ops per operator, seeded and reproducible, cross-checked against arkworks-bn254 in-process as a dev-dependency. All match.
3. Tests cover the edge cases explicitly: inputs 0, 1, modulus−1, R and R² for every op. They also assert `inverse(ZERO) == None`, `(p−1) + 1 == 0` and `(p−1) * (p−1) == 1`.
4. A serde roundtrip over 1,000 random elements satisfies `from_bytes(to_bytes(x)) == Some(x)`. The byte output of `Fr::ONE` is `1` followed by 31 zero bytes, which proves the non-Montgomery wire form.
5. Non-canonical inputs are rejected: `from_bytes(modulus_LE) == None` and `from_bytes([0xff; 32]) == None`.
6. `batch_inverse` on a mixed slice, zeros interleaved with nonzeros, equals element-wise `inverse` with zeros preserved. Test it at lengths 0, 1, 2, 1000.
7. A negative control proves the harness can fail: a deliberately corrupted KAT entry, mutated test-locally, makes the KAT test fail.
8. Bench target (NON-BLOCKING): `tools/bench` prints ns/op for mul, square, inverse, and batch_inverse-per-element at n=2^20, alongside the same measurements for arkworks-bn254. The target is own mul throughput within 2× of arkworks on the build machine. Print the comparative table, record the measured ratio in the handoff, and flag it if above 2×. This target does not block the stage. Numbers are internal; make no public claims.
