# S02 — Poseidon2 Permutation + Duplex Transcript

## Depends on / Inputs
- S01: `Fr`, `constants` crate skeleton with empty `transcript_tags` module.

## Specification
Poseidon2-based Fiat–Shamir transcript for a zkVM whose native arithmetic field is the **BN254 scalar field** \(F_r\). Use the established **width-3 BN254 Poseidon2 instance** and a **rate-2 / capacity-1 duplex challenger**. State width t = 3. Rate = 2. Capacity = 1. S-box exponent alpha = 5. 8 outer full rounds, 56 inner partial rounds. full-round split is 4 before and 4 after partial rounds. partial-round S-box lane is lane 0. Use the latest Plonky3 Poseidon2 construction as a differential oracle for correctness. Note: Latest implementations have added the zero pad (prevent hash collision between [a] and [a, 0]) and +length (into capacity). Pop-from-end challenge order (first challenge = state[1]). `transcript_tags` values: pick a simple deterministic scheme (e.g. sequential u64 per logical message kind), define at minimum tags for protocol suite/version, public inputs, commitment, sumcheck round, sumcheck challenge, evaluation claim, PCS opening — later stages extend the table additively.

## Deliver
- `crates/transcript`: `poseidon2_permute`, duplex `Transcript` (raw observe/sample + typed layer + snapshot/restore).
- `constants::transcript_tags`: the frozen numeric tag table (live in `constants`).
- Committed vector files for the permutation KAT and transcript cases A–E.

public API:

```rust
pub fn poseidon2_permute(state: &mut [Fr; 3]);

pub struct Transcript { /* sponge state + input/output buffers, private */ }
impl Transcript {
    pub fn new() -> Transcript;                       // zero state; protocol init is the caller's job via typed appends
    pub fn observe(&mut self, x: Fr);                 // raw duplex, spec §5
    pub fn sample(&mut self) -> Fr;                   // raw duplex, spec §6
    pub fn append_scalar(&mut self, tag: Tag, x: Fr);
    pub fn append_scalars(&mut self, tag: Tag, xs: &[Fr]);   // length-delimited, spec §9
    pub fn append_bytes(&mut self, tag: Tag, bytes: &[u8]);  // spec §10 encoding
    pub fn challenge_scalar(&mut self, tag: Tag) -> Fr;
    pub fn snapshot(&self) -> TranscriptSnapshot;
    pub fn restore(s: &TranscriptSnapshot) -> Transcript;
    pub fn event_log(&self) -> &[TranscriptEvent];
}
// Lightweight ALWAYS-ON transcript event record (metadata only, never affects challenges):
pub enum TranscriptEvent { Absorb { tag: Tag, n_scalars: usize }, Challenge { tag: Tag } }
pub struct TranscriptSnapshot { /* serde-able via canonical LE; captures sponge state AND both buffers */ }
pub type Tag = u64;   // values defined only in constants::transcript_tags
```

## Acceptance
1. Permutation on KAT: input [0,1,2] → the three expected outputs, byte-exact, from a committed vector file.
2. Differential oracle: ≥ 100 random-input permutation vectors generated by the **Plonky3 reference implementation** (dev-dependency/fixture generator only), committed as files, all matching `poseidon2_permute`.
3. Transcript cases A–E: expected vectors emitted by a committed second implementation — a small spec-pseudocode transcript driver in `tools/` that calls ONLY the Plonky3 reference permutation (never `crates/transcript`) — reviewed and committed as permanent vector files under `crates/transcript/tests/vectors/`. Tests replay each case byte-exact from the files as a genuine differential (no self-oracle: `crates/transcript` never generates its own expected vectors).
4. Case D output ≠ case E output (absorb-length framing works).
5. Output-order test: two samples after a single absorb return state[1] then state[0].
6. Observe-after-sample invalidation: sample/observe/sample differs from sample/sample with the same absorbs.
7. Repeated squeezing: third sample without new material triggers a fresh permutation; verified against a committed vector.
8. Typed-layer separation: `append_scalar(TAG_X, v)` then `challenge_scalar` differs from `append_scalar(TAG_Y, v)` then `challenge_scalar`; `append_scalars` of [a,b] differs from two `append_scalar` calls (per-message framing is real).
9. Byte encoding: `append_bytes` vectors covering empty, 1-byte, exactly-31-byte, 32-byte, and 100-byte inputs, committed; length-prefix makes `"ab"` ≠ `"a","b"` split absorbs.
10. Snapshot/restore: run a 20-operation mixed script, snapshot at operation 10, restore into a fresh `Transcript`, and assert the remaining 10 operations produce identical outputs; snapshot serde roundtrips through bytes.
11. Negative control: one bit flipped in a copy of a case-C vector makes the replay test fail.
