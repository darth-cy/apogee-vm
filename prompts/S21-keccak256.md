## Deliver
- `docs/spec/delegation.md` — THE delegation ABI for all delegation families, frozen here. It covers the ecall numbers, which sit inside S10's precompile range and are append-only, and the argument registers: a7 carries the number, a0 the frame base pointer. It fixes the indirect memory-frame layout rules, invocation-timestamp anchoring, the three request-side zeroings, the static-detachment mechanism for delegation families, and the alignment rules. It also states the delegation-shard ts-window convention `verify_block` enforces, namely min/max invocation ts with no disjointness, citing S20's cycle-owning scoping rule. S22/S23 consume this document as frozen and may only append their frame tables.
- The keccak-f[1600] delegation circuit family ships as `CircuitArtifact` data over the state's bit columns, with its trace routing and prover/verifier wiring through the existing S16/S20 entry points. Add no new entry points.
- Request-side anchor gates go in, added additively to whichever family claims ecall cycles.
- Ship the `guest-sdk` shim `pub fn keccak256(input: &[u8]) -> [u8; 32]`. Sponge and padding run in guest code, one delegation ecall covers each keccak-f block, and a bit-identical in-guest software fallback sits behind the same signature. Freeze that signature: it is the patchable entry point S24's revm hash hook routes through.
- Emulator support: the ecall executes keccak-f on the frame, emits the frame's memory events, and routes an invocation record to the family buffer.
- Ship the `guests/keccak-test` fixture guest.
- Checker: a frozen family-parameterized anchor-tamper checker helper, which S22/S23 invoke by name. It covers three scenarios: drop one invocation record; replay two requests against one invocation; violate each of the three zeroings individually. The block-level TamperHarness hook re-proves one shard, reassembles, and asserts `verify_block` failure. That hook is an additive S20-side extension this stage's acceptance uses.

## Core algorithm
- **Invocation** follows the indirect-access pattern, whose shape is this. A delegation family is invoked, never decoded: it sets no family bit, it runs its own trace alongside the CPU families, and the requesting cycle hands it a base pointer in a register that the delegation side then dereferences at fixed offsets. Prior art carries that invocation over a CSR write, with the CSR number doubling as the delegation-type id; we carry it over an ecall instead. The requesting CPU cycle traps the delegation ecall with a0 holding a word-aligned frame base pointer. The delegation side reads the pointer register, then performs 50 fixed-offset word accesses covering the 200-byte state. The frame is read and written in place in SHA-3 byte order. Frame word j sits at offset 4j. Lane A[x][y] takes index i = 5y + x and occupies words 2i and 2i + 1, low half first. Each read carries its own read-ts pair and 19+19 gap check from the S14 gadget. Writes land at the invocation timestamp within the uniform Δ ∈ {0..3} budget. That follows the per-query-kind Δ-slot assignment, frozen in S12's `MemoryEventLog` timestamp convention and re-frozen as the per-family frame convention in S16's handoff. Quoting that frozen rule, it already provides that distinct addresses may share a slot and that per-address ordering is what matters. All accesses ride the one global memory multiset; add no new argument type.
- **Anchoring** enforces all three request-side zeroings and not two. Gated on the delegation family bit, the requesting cycle's row forces rd to zero, because a delegation request writes no register; forces the mirror read's timestamp to zero; and forces the mirror read's value to zero. The timestamp zero is the anchor proper. The delegation circuit writes its answer tuple stamped 0, a stamp no ordinary cycle can produce, and the request must consume exactly that tuple. Lose it and the requests chain — row k consumes the tuple row k−1 wrote back — so N requests close the permutation against one real invocation, N−1 executions are elided, and the proof still verifies. The value zero is the one an earlier rebuild dropped while restoring the other two, because the headline defect named only the timestamp: the request tuple must mirror the delegation side's exactly on address, timestamp AND value, or the two never cancel. With all three in, exactly one request pairs with exactly one invocation. The exact tuple mechanism is yours, and delegation.md must specify it normatively.
- **Circuit.** The base layer commits the input state as one column per state bit, every bit column booleanity-constrained. It also commits the 50 frame words the memory argument carries, each recomposed from its bits at the input and output boundaries. The 24 rounds unroll as GKR layers whose gates ARE θ/ρ/π/χ/ι at degree ≤ 2, with XOR pairwise as x+y−2xy and χ via a two-step split. Each round is one identical sub-layer block, and ρ and π are pure rewiring. The output state becomes the written frame words. The degree ceiling is not yours to move.
- **Family shape.** Take the 2^16 trace height from the menu. One keccak-f[1600] permutation runs per ecall and per row, with no batching. Employ zero-shard skipping and static detachment accordingly.

## Must-be-exact
1. delegation.md covers every section listed under Deliver, and shim, emulator and artifact ecall numbers assert-match the doc (S10 single-source pattern).
2. Static detachment for delegation families derives membership deterministically from the linked binary, via a link-section marker the shim emits. A user flag alone never decides it. An executed delegation ecall whose family is absent from `VmConfig` is a loud trace-time failure and unprovable.
3. All three anchor zeroings are enforced, and request↔invocation pairing is 1:1.
4. Frame-pointer alignment and frame-bound range checks are present in the emitted artifact, verified in the artifact and not only in source. The class of failure to rule out is this one: a compiler built the pointer-alignment range check and pushed it onto a range-check vector the caller had already drained, so the constraint reached no artifact in any of the four delegation circuits — three of which ended up with an entirely empty 16-bit range channel as a result — while an `assume_no_alignment_overflow` flag sat asserted in source and enforced by nothing. So count the check in the emitted artifact, and let no `assume_*`-style unchecked hypothesis stand anywhere in it.
5. The software fallback is bit-identical to the delegated path; under QEMU the ecall returns `-ENOSYS` and the fallback runs (S10 convention).
6. Every bit column is boolean and every produced word range-checked; padding rows are valid by construction.
7. delegation.md freezes the frame table exactly as Core algorithm pins it, and S22/S23 append their tables under those same rules.
8. One permutation occupies one ecall and one trace row, with no batching. A shard's used-row count equals its invocation count, asserted structurally.

## Acceptance
1. Spec: `docs/spec/delegation.md` exists with all required sections, and a test asserts that shim, emulator and artifact ecall numbers match its table.
2. Permutation differential: the circuit forward-pass output equals a reference keccak-f[1600] on committed vectors including the zero-state KAT. The reference is a dev-dependency oracle, e.g. tiny-keccak.
3. Shim differential: `keccak256` via the delegated path under `Emulator` and via the fallback under QEMU both equal a reference keccak256 on a committed corpus. That corpus includes empty input, 135/136/137-byte rate-boundary inputs, and a multi-block input. The two paths are bit-identical to each other.
4. End-to-end: `guests/keccak-test` proves through the S20 pipeline to a `BlockProof` with ≥1 keccak shard. `verify_block(&VerifyingKey, &BlockProof, &PublicInputs)` returns Ok, and global read/write roots reconcile across CPU and delegation shards.
5. Witness-tamper twin (circuit cell): re-prove with one corrupted state-bit/lane cell in the delegation witness, and verification fails with the expected error class. The honest twin passes, and structural count assertions run.
6. Anchor tamper (linkage): three cases run separately. (a) A request with no matching invocation, its record dropped, fails via the global multiset. (b) Two requests replayed against one invocation fail. (c) Each of the three zeroings, violated on the request row one at a time, fails. Each of the three has shipped as a real regression; treat none as theoretical.
7. Alignment negative: a non-word-aligned frame pointer is unprovable, failing via the artifact's alignment check.
8. Detachment/zero-shard: a guest without the ecall derives a family set excluding keccak, and the test asserts it. A guest linking the shim but never calling it proves with zero keccak shards and verifies.
9. All checker validators pass on the new artifacts, artifacts are regenerated and diffed in CI, and the degree-2 construction assertion covers every new gate.
