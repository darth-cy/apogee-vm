# S16 — Vertical slice: add/sub family end-to-end

This is the spine gate the whole roadmap hangs on. You prove and verify a real tiny guest through every layer of the stack, with tamper twins failing in three distinct ways.

**The constraint vocabulary.** No reference document ships with this stage. These five gadgets are the family's semantic vocabulary, reused unchanged. A word now fits in one Fr element - Fr wraps at `r` and RISC-V at 2^32.

- **16+16 range check.** Every produced word needs an explicit proof it is below 2^32; the wide field will not do it for you. Witness one column, the high halfword `h`, and send two keys to the 16-bit channel: `h`, and the linear form `x − 2^16·h`. Keys may be linear forms, so the low half costs no column: one column, two lookups, per word.
- **Wrap/carry bits.** Arithmetic takes the shape `<exact expression over words> = <result> + 2^32·<wrap>`, `wrap` witnessed and pinned to {0,1} by booleanity. One bit suffices only because the decoder never lets a third addend go live — R-type sets `imm = 0`, I-type sets `rs2 = x0` — so the wrap cannot reach 2. The equation is worthless without the range check on its result: at `wrap = 0` it happily accepts the unreduced sum.
- **Copower, plus a mandatory direct check.** A bound varying row to row (`x < p`) has no fixed-domain table. Witness `p' = 2^32/p`, constrain `p·p' = 2^32`, range-check `x·p'` to [0, 2^32). Half that equivalence is false over a field: `p'` is a unit in Fr, so `x` roams a coset of 2^32 elements while the scaled value looks small. A scaled bound is only HALF a bound — any column used as its left factor must ALSO carry its own 16+16 check, enforced as a mechanical `checker` rule.
- **Witnessed-inverse is-zero.** Non-negativity arguments die here: `c0 = 1, c1 = r − 1` sums to zero and forges register equality. Test a word `x` for zero with a flag `z` and a witnessed inverse `inv`: `z·x = 0` and `z + x·inv − 1 = 0`. That pins `z` to {0,1} by itself, and is sound because a nonzero 32-bit difference stays nonzero in Fr.
- **Packed decoder mask.** The decoder hands you the family flags as ONE column, the packed bitmask. Carry that column and the per-bit booleans, tied by one degree-1 constraint `mask − Σ 2^i·bit[i] = 0`. Exclusivity comes from the table's domain — only legal masks are rows of it — never from booleanity, which permits any subset including all-zero, where every gated constraint goes vacuous and `rd` is free. Add/sub's legal set is the one-hot `{1, 2, 4, 8, 16}`, and the domain lookup is `(execute flag, mask) ∈ {(0,0)} ∪ {(1,m) : m legal}` so padding stays legal. Gating by a family bit costs a degree; gate on a decoder flag that already arrives gated.

## Deliver
- The `prover` crate provides `fn prove_shard(&ProvingContext, &TraceArchive, family, shard_idx) -> ShardProof`, plus the minimal global commit phase needed for a one-family-plus-init/teardown proof: statement binding, memory-column commitments and global challenges.
- The `verifier` crate provides `fn verify_shard(&VerifyingKey, &ShardProof, &PublicInputs) -> Result<(), VerifyError>`, the single entry point. `VerifyError` is an enum with distinct classes, at least {Statement, Constraint, MemoryArgument, Lookup, Opening}. Structure the crate as the frozen no_std verifier core under a thin std wrapper. The core holds statement binding, transcript replay, sumcheck verification, the GKR claim-chain, the LogUp root checks and the S20 reconciliation checks. It also holds a curve-free Mercury field-side/deferred-scalar module, shared with `pcs`, that treats G1 limbs as opaque 4-Fr blobs. transcript/sumcheck/gkr/poly, and pcs's field-side module, must be no_std-compatible. S26's guest links this core, and re-implementation is forbidden.
- The family-registration API is a `ProvingContext`/`VerifyingKey` builder that takes the per-family set derived from `VmConfig`: `FamilyId` per S11's frozen table, `CircuitArtifact`, trace-buffer routing and menu height. Name it explicitly as the surface E17–S19 and E21–S23 use to add families with zero prover/verifier edits.
- The `ShardProof`, `VerifyingKey` and `PublicInputs` structs have a fixed shape per master and canonical LE serde.
- The add/sub family ships as a `CircuitArtifact`. It carries semantics constraints for at least ADD, SUB, ADDI, LUI and AUIPC, plus the exit/commit ecall path the guest needs. Pin the default roster at exactly those; a wider roster is allowed, and either way the family-partition check must claim every pc of the guest.
- The `checker` crate gains the reusable tamper-twin harness `TamperHarness`: given a proving context, a target cell (`PolyAddress` plus row) and a mutation, it re-proves and asserts failure with an expected `VerifyError` class.

## Core algorithm
The pipeline has five steps.
1. Build the guest with S10, decode it and derive `VmConfig` and `ProgramIdentity` with S11, then execute it and record the trace with S12.
2. Absorb the statement binding in exactly the master's frozen pre-fork order, take per-column Mercury commitments for all memory-subtree columns, then squeeze the global memory challenges.
3. Seed the shard-local transcript with the global state digest, the family id and the shard index. Absorb that shard's witness commitments, and only then draw the local challenges: the eq point r, g/β, and the RLCs.
4. Run the forward pass, then the backward pass, then the final claim-merging sumcheck. That sumcheck reduces ALL base-layer claims to ONE point: the zerocheck side claims and the product-tree and fraction-tree bottoms. Take the RLC over columns, produce one batched Mercury opening, and emit the `ShardProof`.
5. Verification replays the transcript and checks everything through the single entry point. Pairing work happens only inside `pcs` verification; the base prover never pairs, per master. `batch_verify` takes the vk's `SrsVerifier` (per S08/S09's frozen signatures), and `batch_open` takes the commitments produced by the commit phase (per S09's frozen signature).

The tiny guest is a straight-line chain of 32-bit additions and subtractions over the pinned roster. It commits its result word and exits through the ecall path.

Parallelize with rayon over independent rows and columns in a fixed reduction order. Results must be independent of thread count and scheduling, so parallel and single-threaded runs give byte-identical proofs.

## Must-be-exact
1. S1: the pre-fork absorb order is exactly the master's frozen list. Reference it, implement it once, symmetrically in `prover` and `verifier`. No item may be skipped, and no local challenge may be drawn before its commitments.
2. Local transcript seeding works as follows. The global state digest := challenge_scalar(TAG_GLOBAL_STATE_DIGEST) is drawn once on the global transcript, after the memory challenges, and its tag is frozen in constants. Each shard transcript starts from Transcript::new() and absorbs (digest, family id per S11's FamilyId table, shard index) as one typed message, with the frozen domain-separation tags from `constants`. Then comes the per-shard ts-window binding absorb: one typed message immediately after that seed triple. S16 binds the trivial full-execution window; S20 generalizes the value. The window field lives in `PublicInputs`, or in the shard's public record, so `verify_shard` already replays it.
3. S7: each shard carries exactly ONE Mercury opening. The claim-merge sumcheck ends at one point. The column RLC challenge is drawn only after all evaluation claims are absorbed. The variable-binding order matches Mercury's split per the S08/S09 handoff. Only committed-column `BaseClaim`s enter the claim-merging sumcheck and the single batched opening. Virtual-setup `PolyAddress` claims are discharged instead by the verifier's direct closed-form evaluation at their own points.
4. `ShardProof` has a fixed shape: no optional sections, no data-dependent lengths. AccumulatorEntry lists are produced ONLY by deferred verification (batch_verify_deferred) during recursion (S26) and discharged at the endgame (S27/S28). ShardProof and BlockProof carry none, since base verification pairs inside pcs.
5. `VerifyingKey` conveys `VmConfig`, `ProgramIdentity` and the SrsVerifier: the S07 g1 generator, g2_gen, g2_tau and digest. That SrsVerifier is the only SRS material the verifier may use. The key also conveys the family artifacts, so its canonical serialization contains the full `CircuitArtifact`s in the S13 schema, canonical LE. That is everything `verify_shard` needs beyond proof and public inputs. The vk travels as recursion-guest input bytes (S26).
6. S9, the soundness floor, is non-deferrable. Apply the vocabulary above literally: every produced word — `rd` and `final_pc` — is range-checked 16+16 through the S15 channel, every wrap/carry/selector bit has booleanity, and one-hotness comes via the packed decoder-mask domain. rd = x0 follows the S14 convention. ADD/ADDI/AUIPC are one selector-gated `a + b = rd + 2^32·wrap`, SUB is `a − b = rd − 2^32·wrap`, and `final_pc = initial_pc + 4 − 2^32·pc_wrap`.
7. Each prover phase boundary exports a self-contained snapshot that includes the transcript sponge state, and proving can resume from any of them. The boundaries are post-execution, post-commit, post-GKR, post-opening and final. Phase snapshots ARE the corresponding phase sections of the S12-frozen TraceArchive container, and wall-clock goes in S12's per-phase timing fields. S16 defines the section schemas for the phases S12 left empty. Resume = `TraceArchive::import` plus the S16 resume API. Intra-section payloads use single wire encoding, canonical LE under `serde`/`postcard` framing.
8. One verification path: the CLI verifier and every test call `verify_shard`. There is no second code path.
9. Tests target blind cells: the harness must be able to address cells pinned only by the memory argument or by a lookup channel, not by any row constraint.
10. `prove_shard` performs the shard-local steps only. The global phase is a separate public entry point, `global_commit_phase(...) -> GlobalCommitState`, whose output enters `prove_shard` via `ProvingContext`.
11. `ProvingContext` is built once per program and holds only cross-shard state. That state is the `VerifyingKey` proven against, the registered per-family set, prover-side SRS material, and the `GlobalCommitState` from `global_commit_phase`. It holds no per-shard state, so one context serves every shard of every family.
12. `global_commit_phase` is shard-count-generic from the start, so S20 generalizes it to multi-shard blocks without a second entry point. It takes the statement descriptor and the memory-column commitment inputs for every shard of every family. It returns a `GlobalCommitState` carrying the global transcript state, the memory-column commitments, the global memory challenges and the global state digest. S16 calls it with one shard per family, S20 with many.

## Acceptance
1. Honest twin: the tiny guest builds, its S12 trace passes the QEMU differential, `prove_shard` produces proofs for the add/sub shard and the init/teardown shard, and `verify_shard` returns `Ok` for both. Structural count assertions run on the non-empty proofs: round counts, claim counts, fixed proof byte length.
2. Tamper via `TamperHarness`: one cell of a SEMANTICS column (an rd value, say, or a wrap bit) fails with the `Constraint` class.
3. Tamper: one MEMORY EVENT cell, either value or timestamp, fails with the `MemoryArgument` class.
4. Tamper: one LOOKUP MULTIPLICITY cell fails with the `Lookup` class. (Items 2–4 are the stage gate: three distinct error classes on screen.)
5. Each S1 statement twin fails with the `Statement` class. The twins mutate `ProgramIdentity`, the public-I/O digest and the static `VmConfig`. A SEPARATE twin mutates the per-proof per-family shard counts, another mutates the SRS digest, another swaps one memory-column commitment, and a last one replays an honest proof against different `PublicInputs`. The statement descriptor is static VmConfig plus per-proof per-family shard counts, absorbed as two adjacent typed messages and frozen in S11's handoff.
6. S7 structural tests assert three facts. The `ShardProof` holds exactly one `MercuryProof`. All `BaseClaim`s merge to one point, asserted in the prover and re-derived in the verifier. The transcript event log shows the column-RLC challenge sampled after every evaluation-claim absorb.
7. S9 negative controls: an unreduced-sum witness (wrap = 0, rd = a+b ≥ 2^32) fails via the range channel; a non-boolean wrap bit fails; an all-zero family mask fails on the Decoder domain lookup, not on booleanity; a `final_pc` out of the 32-bit space fails.
8. S5/S6 at full scale: the transcript event log shows the eq point r and every layer-RLC challenge drawn post-commitment in spec order. The per-layer batched-claim invariant (≤ 1 outstanding claim after batching) holds across the real family's backward pass.
9. Snapshot/resume: interrupt after post-commit and after post-GKR, resume from the snapshot, and obtain a `ShardProof` byte-identical to the uninterrupted run.
10. Serde: `ShardProof` and `VerifyingKey` round-trip byte-identically in canonical LE, and the CLI verifies the dumped proof file and rejects a bit-flipped copy.
11. `TamperHarness` negative control: pointed at a cell mutation that should NOT affect validity, for example an unused scratch slot, it reports "still verifies" rather than a false failure, proving the harness can distinguish.
12. Verifier signature audit: `verify_shard` takes only `(&VerifyingKey, &ShardProof, &PublicInputs)`, and a compile-time/API test pins the signature.
13. Teardown↔output binding: re-prove with one committed output byte, or one teardown final-value cell, changed in the trace while `PublicInputs` keeps the honest digest. Verification must fail via the teardown binding mechanism stated in S14's handoff, with its expected error class.
