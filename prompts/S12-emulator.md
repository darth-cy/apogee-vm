# S12 — Emulator + trace generation

## Depends on / Inputs
- S10 supplies `ProgramImage`, `loader::load_elf`, the ecall ABI table with its fd conventions, `io_digest`, the fixture corpus and QEMU tooling.
- S11 supplies `Instr`, `decode`, `DecodedTables` and `VmConfig` (family set plus heights), plus the family-partition guarantee.
- S03 supplies `MultilinearPoly` (small-type backing) for column export; S01 supplies `Fr` with canonical LE serde.
- The master **Memory argument** invariant governs: 38-bit timestamp, STEP = 4, Δ ∈ {0,1,2,3}, address spaces registers / RAM / PC.

## Deliver
- The `emulator` crate provides `Emulator`, a step-accurate RV32IMAC interpreter over a `ProgramImage`. It also provides ecall dispatch implementing the S10 ABI (read/commit/hint, exit, `-ENOSYS` for unknown numbers), a plain fast `run` path without tracing alongside a tracing path, and the QEMU differential harness.
- The `trace` crate provides `MemoryEventLog` with "last-access" bookkeeping, per-family trace buffers (`FamilyTraces`), `TraceArchive` export/import, and `ShardPlan` estimation from cycle profiles. It also provides the frozen constructor `TraceArchive::from_execution(FamilyTraces, MemoryEventLog, CycleProfile, io streams, timing) -> TraceArchive` and the frozen post-execution accessors `family_traces()`, `memory_log()`, `cycle_profile()` and `io_streams()`. `trace_run` keeps its Must-be-exact 8 signature, and the archive is built from its outputs through that constructor, which is the pinned choice.
- The fixture suite covers every RV32IMAC instruction with single-opcode guest programs: each of the nine AMOs, LR/SC, every M op, plus an RVC-dense build. It also contains `guests/fib` and an allocator-exercise guest that churns Vec/Box through the bump allocator.

## Core algorithm
- **Semantics.** You emulate RV32IMAC on a single hart. With one hart, no interrupts and no DMA, the A extension's *atomicity* is free, so ten of the eleven RV32A instructions lower unconditionally: an AMO is load → ALU op → store, the `aq`/`rl` ordering bits are no-ops, and `LR.W` behaves as `LW`. What does not go away is arity. An AMO reads memory, writes memory *and* writes rd in one instruction, which no RV32I instruction does, so it is one row with four memory queries when traced: rs1 read, rs2 read, the RAM read-modify-write (one query, since a query carries both a read value and a write value at one address), and the rd write. `lw`, `sw` and `lr.w` need only three. `lr.w` would therefore have fitted the load family, but the whole extension stays in one circuit anyway, which is easier to audit than splitting it on an `lr`-versus-`sc` distinction that has nothing to do with the rest of the design.
  `SC.W` is the eleventh, and **it always succeeds**: it writes memory and sets rd ← 0, per register D1. The spec requires `SC` to fail when there is no valid reservation, so an unpaired `SC` must not write memory, and always succeeding diverges from that. It is a *conformance* deviation and never a soundness one — the verifier still knows exactly which program ran, so "this program produced this output" holds unchanged — and fidelity would cost a reservation flag in machine state for no gain, since LLVM never emits an unpaired `SC`, never relies on spurious failure, and the standard CAS loop exits on its first pass. Document the deviation and whitelist it in the differential harness.
- **Timestamps.** Cycle c occupies base timestamp c·4, and each memory query takes an in-cycle slot Δ ∈ {0..3} — the uniform four-slot budget. Atomics cycles use all four slots; other families leave slots unused, which keeps the stride uniform so nothing needs re-auditing per family, at the price of a quarter of the timestamp range. The clock is 38-bit, and exceeding it is a loud named failure, never a wrap.
- **`MemoryEventLog`.** Each memory query produces one event, carrying address space (REG/RAM/PC), address, write ts (= c·4 + Δ), read value with its read ts, and write value. PC is an address space , so every cycle reads pc and writes next_pc. "Last-access" tables hold the per-address last write ts and value. They fill each event's read side during the single pass, and this bookkeeping is exactly what later stage's witness fill consumes.
- **Trace generation.** Run a deterministic single-pass loop: execute once, route each cycle's record to exactly **one** family buffer (the family owning that pc in `DecodedTables`), and append memory events to the one global log. There is no second execution pass and no pub/sub. Each per-cycle record carries at minimum cycle number, pc, next_pc, and the cycle's per-Δ-slot memory-event values (Must-be-exact 7).
- **`TraceArchive`.** This is the self-contained snapshot artifact. The container schema declares all five phase boundaries: post-execution, post-commit, post-GKR, post-opening and final. Each boundary carries per-phase wall-clock timing metadata. This stage produces and fills only the post-execution phase. The schema and timing fields are frozen now, so later stage's prover appends the later phases and any future bench harness reads timings from these boundaries. Timing metadata lives in a delimited section separate from the deterministic payload.
- **`ShardPlan`.** Derive it from the per-family cycle profile and the `VmConfig` heights (menu {2^16, 2^18, 2^20, 2^22}). Shard count per family is ceil(occupancy / height). A family with zero occurrences in this execution plans **zero shards**.
- **Interpreter and log representation.** Machine state is a plain struct: registers as `[u32; 32]`, the pc, and RAM as a sparse map of 4 KiB pages. Dispatch is a flat `match` over S11's `Instr`. `MemoryEventLog` stores a flat append-only vector of fixed-width records in cycle-then-Δ order. Later stages consume that order, and it serializes straight into the archive payload. Last-access tables hold the last write ts and value in a directly indexed array over the 32 registers and pc, plus a hash map keyed by RAM word address. `GuestIo` holds the fd 0 input bytes and the hint stream. `Execution` holds the final register file, exit code, cycle count and recorded fd 0/1 streams. `CycleProfile` holds per-family cycle counts keyed by family id.
- **Differential harness.** Because S10's ecall convention is the Linux one, qemu-riscv32 executes the identical binary under the identical ABI, which turns ISA conformance from hand-written vectors authored and must trust into a differential test against a project with a decade of maintenance behind it. That is the whole reason the ABI was chosen, and it keeps paying out: a mis-expanded compressed instruction desyncs the loader's linear sweep and produces silently wrong execution, which QEMU catches loudly; the `SC.W` divergence is known in advance and whitelisted; and a precompile-range ecall returns `-ENOSYS` there too, so the guest's software fallback fires and one source tree serves both executors. qemu-riscv32 is the only oracle, and spike is not added: a second implementation of the same specification buys surface, not coverage. Run each fixture under QEMU with one instruction per translation block and CPU-state logging (`-d nochain,cpu`). Compare the dumped x0–x31 and pc against the emulator's trace, normalizing log formatting only. The required corpus is exactly the Deliver coverage, and fixtures beyond it are welcome but not required.

## Must-be-exact
1. The differential oracle compares per-instruction register-state traces against qemu-riscv32 on the fixture suite. The SC.W deviation is the **only** whitelisted divergence, and the whitelist names the instruction, the rule, and the reason it is conformance rather than soundness.
2. Ecall dispatch matches the S10 ABI table exactly — one source of truth, test-asserted. The fd 0/1 streams are recorded into the archive so `io_digest` is recomputable offline from it.
3. Keep four-slot timestamp discipline throughout: every event's Δ ∈ {0..3}, stride 4 per cycle, and a read ts strictly preceding the write ts at the same address. The complete timestamp convention is pinned here as ts = 4·cycle + Δ, with the per-query-kind Δ-slot assignment given per instruction class. Δ=0 is the pc read / next_pc write pair, present every cycle. Δ=1 is the rs1 read, modeled as a read plus a write-back of the same value sharing its slot. Δ=2 is the rs2 read under that same modeling, or a load's data read. Δ=3 is the rd write or the store's data write. The atomics 4-query frame uses all four slots: Δ=0 the pc pair, Δ=1 rs1, Δ=2 rs2, and Δ=3 the RAM read-modify-write with the rd write-back sharing that slot. The slot-sharing rule is pinned explicitly. Queries at distinct (address space, address) pairs MAY share a Δ slot, but two queries at the same address never share one. A register read's read + write-back pair is one query, not two. Ecall rows are pinned as part of this same frozen timestamp convention. An ecall cycle logs the Δ=0 pc pair, the a7 read at Δ=1, and the a0 return write-back at Δ=3. It also reads exactly the argument registers its syscall number uses, a0–a5 per the ABI table; those reads share the Δ=1 and Δ=2 slots under the slot-sharing rule, because they sit at distinct register addresses. Syscall buffer traffic, meaning read/commit/hint bytes, materializes as ordinary RAM events under the same 4-slot and 38-bit discipline. Each transferred word occupies its own synthetic cycle's Δ slots, pinned explicitly: Δ=0 carries the pc pair re-writing the unchanged pc, and Δ=3 carries the word's RAM read or write. PC continuity holds, and the ecall's completion writes the real next_pc. S14's multiset fill and S16's ecall-row constraints cite this convention rather than inventing one.
4. Routing is total and deterministic. Every executed cycle lands in exactly one family buffer, and per-family counts sum to total cycles. An unclaimed pc is impossible after S11's partition; if one appears, it is a loud internal error, never a skip.
5. `MemoryEventLog` carries a multiset self-check API. It recomputes read/write multiset balance directly from the log plus derived init/teardown sets (every read matched by the prior write or an init; final values collected for teardown), and checks gap non-negativity. This is a trace-level validator, independent of any circuit, with a negative-control test.
6. `TraceArchive` round-trip is byte-identical, and two runs of the same guest and input produce archives whose deterministic payloads are byte-identical — the timing section is excluded by construction, not by fuzzy comparison.
7. Family buffers export columns as small-type `MultilinearPoly` values with recorded occupancy. The minimum per-cycle record content of a family buffer is pinned. Each record exports the cycle number, pc, next_pc, and the cycle's per-Δ-slot memory-event values as columns: the rs1/rs2 read values, the rd write value, and load/store data. Later witness generation consumes these columns directly rather than re-joining the `MemoryEventLog`. Padding-row *content* is downstream's job and buffers must not invent it.
8. Freeze roughly these signatures (define associated aux/error types as needed):
   `pub fn run(image: &ProgramImage, io: &GuestIo) -> Result<Execution, EmuError>;`
   `pub fn trace_run(image: &ProgramImage, io: &GuestIo, tables: &DecodedTables, config: &VmConfig) -> Result<(FamilyTraces, MemoryEventLog, CycleProfile), EmuError>;`
   `impl TraceArchive { pub fn export(&self, w: impl Write) -> Result<..>; pub fn import(r: impl Read) -> Result<TraceArchive, ..>; }`
   `pub fn plan_shards(profile: &CycleProfile, config: &VmConfig) -> ShardPlan;`
9. Misaligned data accesses (LW/SW/LH/SH/LR/SC/AMO at unaligned addresses) are a fatal, named guest error in both the `run` and `trace_run` paths, never silently rotated, split, or emulated.
10. The x0 trace convention is pinned: reads of x0 are logged as ordinary REG addr-0 events, instructions with rd = x0 log a write-back of value 0, and x0 is initialized like x1..x31. S14's R2-5 freedom is thereby scoped to the constraint-side enforcement mechanism over this pinned trace behavior.
11. The `TraceArchive` container is postcard-encoded with a fixed section table: deterministic payload sections first, the delimited timing section last. The pinned default is no compression, because an uncompressed canonical encoding holds item 6's byte-identity most simply and the hot path is elsewhere. Compression on top of it stays permitted, provided item 6 still holds.
12. `run` and `trace_run` share one instruction-execution core; the tracing path differs only in that each memory query is also handed to an event sink, so neither path carries its own copy of instruction semantics.

## Acceptance
1. QEMU differential: full fixture suite (every RV32IMAC instruction incl. all AMOs/LR/SC/M ops, RVC-dense build, fib, allocator exercise) runs with per-instruction register traces equal to qemu-riscv32's, and SC.W sites match under the documented whitelist rule. Fixtures are committed and pinned by hash.
2. Harness negative control: an injected single-register perturbation in the emulator trace makes the harness report a mismatch at the exact instruction, proving the oracle comparison can fail.
3. Self-check positive: multiset balance holds for fib and the allocator exercise, heap traffic included.
4. Self-check tamper twin: corrupting one `MemoryEventLog` event makes the self-check fail naming address space, address, and ts. Corrupting one PC event likewise fails, since PC continuity is part of the multiset.
5. Timestamp scan: a test walks the full log asserting Δ ∈ {0..3}, stride 4, and non-negative gaps, and an `amoadd.w` loop fixture demonstrably occupies all four slots in one cycle.
6. Routing holds for fib: per-family cycle counts sum to total cycles, and each cycle's assigned family equals an independently recomputed table-owner of its pc. The atomics fixture routes its AMO cycles to the atomics buffer, and its derived `VmConfig` includes that family.
7. Archive: export → import → export is byte-identical, and two independent runs produce hash-equal deterministic payloads. The imported archive yields cycle count, per-family occupancy, and recorded fd 0/1 streams without re-execution, and `io_digest` recomputed from those streams equals the value from the live run. A rebuild test imports the archive and rebuilds the family columns without re-execution via the `family_traces()`, `memory_log()`, `cycle_profile()`, `io_streams()` accessors.
8. Phase boundaries: the archive schema enumerates all five phases and the post-execution phase carries its timing; a test asserts later phases are present-but-empty and rejects an archive claiming a filled phase out of order.
9. `ShardPlan` edge cases hold: synthetic profiles with occupancy 0 / 1 / exactly-height / height+1 yield 0 / 1 / 1 / 2 shards. A zero-occurrence family plans zero shards, and the plan is a pure function of (profile, config).
10. A precompile-range ecall returns `-ENOSYS` under the emulator and the guest's software fallback completes, matching QEMU behavior.
11. Misalignment fixture: a guest performing an unaligned LW/SW (and one unaligned AMO) fails with the named fatal guest error in both `run` and `trace_run`, and no partial trace is emitted.

## Handoff
Freeze the `Emulator` public API (`run`/`trace_run`, `GuestIo`, `Execution`, `EmuError` classes). Freeze the `MemoryEventLog` event schema: fields, address-space tags, the complete timestamp convention of Must-be-exact 3, and the x0 trace convention of Must-be-exact 10. That convention is the per-query-kind Δ-slot assignment frozen in S12's `MemoryEventLog` timestamp convention and re-frozen as the per-family frame convention in later handoffs. Freeze the log's API too, including the `touched_addresses()` and `final_state()` (per-address final value + ts) accessors, which later teardown fill and enumeration cross-check consume. Freeze the `FamilyTraces` column-export contract, including the frozen column-name list for the pinned per-cycle record content of Must-be-exact 7. Freeze the `TraceArchive` container (section layout, five phase tags, timing-metadata schema, determinism boundary) with the frozen constructor `TraceArchive::from_execution(FamilyTraces, MemoryEventLog, CycleProfile, io streams, timing) -> TraceArchive` and the post-execution accessors `family_traces()`, `memory_log()`, `cycle_profile()`, `io_streams()`. Freeze `CycleProfile`, `ShardPlan` with `plan_shards`, the QEMU harness invocation and whitelist format, and fixture paths. Record measured cycle counts and per-family occupancy for fib and the allocator exercise.
