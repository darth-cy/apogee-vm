# S11 — Decoder + program identity

This stage is on the decoded-table field set, pc/2 indexing, MINUS_ONE padding, the family partition and the identity/determinism argument.

## Depends on / Inputs
- S10 supplies `ProgramImage`, `loader::load_elf`, and the S10 differential-test fixtures and harness.
- S08/S09 supply the `pcs` Mercury commit (single-poly), the commitment primitive underneath `ProgramIdentity`.
- S07 supplies the `Srs` loader and S02 the `Transcript` typed layer, which is the identity-digest mechanism. S01 supplies `Fr` canonical LE serde and S03 `MultilinearPoly` for the table columns.
- The master invariants **VmConfig / program identity** and **Trace heights** are normative here.

## Deliver
- The `isa` crate holds `Instr`, the decoded RV32IMAC instruction model, and `decode(word: u32) -> Instr` for expanded 32-bit words; the loader guarantees no compressed form reaches it.
- The `program` crate holds per-family `DecodedTables`, `VmConfig` derivation (static detachment), and `ProgramIdentity`.
- A CLI/tool subcommand prints the human-readable decoded table for any ELF, showing pc, mnemonic, decoded fields and owning family, plus the program identity.

## Core algorithm
- **Table shape.** There is one table per circuit family and one row per **halfword** slot, indexed by `pc/2`, so row i is pc = 2i. The row fields are `pc, next_pc, rs1_index, rs2_index, rd_index, imm, funct3, family_extra_mask`. `next_pc` carries the sequential fall-through pc directly, never a length bit, so the fall-through constraint is the linear `final_pc = next_pc_from_decoder`. The loader is free and the circuit is not: anything computable offline belongs in this table. Per-family field selection is a bitmask that may drop fields a family never uses, but `pc` and `next_pc` are mandatory in every family. The bitmask is not a knob: it is a derived description of the lookup tuple the family circuit already built, so every field pushed into that tuple pushes `true`, every skipped one pushes `false`, and an assertion checks the `true` count against the tuple's arity. "A decoder-derived column the lookup does not cover" is then not expressible. Each family's `DecodedTables` columns are MINUS_ONE-padded to EXACTLY that family's `VmConfig` trace height, which is strictly greater than the program's live rows; otherwise preprocessing fails loudly. Table length therefore equals the family's shard column length, automatically an even variable count, and `program_identity` commits the columns at that padded size.
- **The padding sentinel is `Fr::MINUS_ONE`, never 0** (master invariant). Mid-instruction slots, non-instruction slots, and pcs owned by other families all pad to MINUS_ONE in every field. pc = 0 is a valid pc, so an all-zero row would be claimable.
- **Representations.** `Instr` is an enum: one variant per mnemonic carrying that form's fields, with accessors projecting each onto the row fields above. Store `DecodedTables` column-major. Each column uses the narrowest small-type array its live values fit, beside a one-bit liveness column, and MINUS_ONE is materialized only at `MultilinearPoly` lift or commit time. `family_extra_mask` packs, little-endian, one bit per family-local row kind or sub-opcode discriminator beyond the shared fields. Bit positions are per family in canonical ascending order, frozen in `constants` and append-only, and bit 0 of the add/sub/lui/auipc mask is the system row kind. Document the encoding in the crate CLAUDE.md.
- **Families partition the program**: derivation asserts every executable pc is claimed by exactly one family. A pc claimed by zero families is a loud preprocessing failure ("Not all opcodes supported: pc=…"), by two an internal assertion failure. Family granularity must match the roadmap's circuit families (add/sub/lui/auipc; jump/branch/SLT; shift/bitwise; mul/div; mem word; mem subword; atomics), since later stages build circuits against these tables. System instructions have a pinned owner: ECALL/EBREAK/FENCE pcs are claimed by the add/sub/lui/auipc family as a named system row kind, making the partition total by construction.
- **Static detachment**: the family set is derived from the decoded program. A program with no A instructions gets no atomics family in `VmConfig`, and the same holds for every family. The preprocessor derives the set, never a user flag.
- **`VmConfig`** (static part) carries the family set, the per-family trace heights from the menu {2^16, 2^18, 2^20, 2^22}, and `bytecode_size_words`. Per-proof shard counts are NOT in it: they vary per execution and are absorbed pre-fork per the master's statement-binding order. Default heights assign 2^22 to add/sub/lui/auipc, jump/branch/SLT, shift/bitwise, mem word and mem subword; 2^20 to mul/div and to init/teardown image-address enumeration; 2^16 to atomics. `ProgramParams` carries `bytecode_size_words`, the per-family heights and the code version.
- **`ProgramIdentity`** is a deterministic commitment over the per-family decoded table columns plus the static `VmConfig`. It uses Mercury/KZG commitments from `pcs` over the public SRS, combined into one digest via the S02 typed transcript. That transcript is the single pinned mechanism, and no ad-hoc Poseidon2 hashing path exists. Compute it from the post-load expanded `ProgramImage`, never from raw ELF bytes — those carry build paths, timestamps and debug sections — in canonical LE wire encoding throughout. State the binding argument in the crate CLAUDE.md. The verifier never sees an ELF and never checks that a commitment came from one; every step from ELF to commitment is deterministic, so anyone can rerun it and reproduce the value, and that commitment *is* the program's identity, the way a code hash is a contract's. It behaves like a public key: a proof checked against a prover-supplied identity honestly proves "*some* program ran correctly", which is true and useless. The verifier therefore takes the identity from a channel the prover does not control — a registry, a hardcoded constant, an operator value — never from the proof. That is also why S10's reproducible builds are essential: if two honest builds of one source disagree, nobody can independently confirm a registry entry.

## Must-be-exact
1. `decode` covers all of RV32IMAC's 32-bit forms.
2. Indexing is pc/2 with addresses preserved, and jump/branch target alignment is validated at 2-byte granularity. 
3. MINUS_ONE padding appears everywhere a slot is not a live instruction of that family, and no all-zero row is representable. Each family's columns are MINUS_ONE-padded to EXACTLY that family's `VmConfig` trace height, which is strictly greater than the program's live rows; otherwise preprocessing fails loudly. Table length therefore equals the family's shard column length, automatically an even variable count, and `program_identity` commits the columns at that padded size.
4. The family-partition assertion holds: exactly one family claims each pc. An ELF containing an A instruction, decoded under a config where atomics were detached, fails loudly. That failure is the safety mechanism that makes detachment sound.
5. `bytecode_size_words` is an explicit input to derivation and to identity (default 2^20 = 4 MB ceiling), never silently inferred, and programs exceeding it fail loudly.
6. Identity is a pure function of `(ProgramImage, family set, heights, bytecode_size_words, code version)`, independent of machine, OS, thread count, and run. It is not a function of the program's input, trace, cycle count or who is proving: the table says what the program *is*, and the per-execution multiplicity columns counting how often each row ran live in the witness, never here. Any of those five inputs changing is a versioning event with no in-place migration: re-registering every deployed program is the only path.
7. Table columns are exportable as `MultilinearPoly` values. Later stages consume them as committed setup.
8. Freeze roughly these signatures (define associated error/aux types):
   `pub fn decode(word: u32) -> Instr;`
   `pub fn decode_program(image: &ProgramImage, params: &ProgramParams) -> Result<(DecodedTables, VmConfig), ProgramError>;`
   `pub fn program_identity(tables: &DecodedTables, config: &VmConfig, srs: &Srs) -> ProgramIdentity;`
9. The digest recipe is fixed, framed per message. A fresh S02 typed transcript, opened under a `PROGRAM_IDENTITY` domain tag in `constants`, absorbs the code version first. It then absorbs the static `VmConfig` as one typed message carrying the family set in ascending FamilyId order, the per-family heights, and `bytecode_size_words`. It then absorbs one typed length-delimited message per family, in ascending FamilyId order, carrying that family's per-column Mercury commitments in frozen column order, each G1 point as 4 Fr affine limbs. Squeezing one Fr yields the identity.

## Acceptance
1. Decode differential: the decoded fields (mnemonic, rs1/rs2/rd, imm, funct3) agree with `objdump -d` output for every instruction in the S10 fixture corpus and for a handcrafted per-opcode word list. That list covers all RV32IMAC opcodes, including each AMO, LR/SC, and the M-extension ops. Fixtures are committed and pinned by hash.
2. Negative decode controls: a corpus of malformed or reserved 32-bit words all produce error. The corpus includes at least one near-miss per major opcode format (wrong funct7, bad funct3).
3. Partition positive: for fib, every executable pc lands in exactly one family table. A test recomputes the claimed-pc union and compares it against the image's instruction slots.
4. Partition negative: a fixture guest containing `amoadd.w`, decoded with atomics force-detached (test hook), fails loudly with the offending pc named.
5. Static detachment: fib's derived `VmConfig` excludes the atomics family, an atomics-using fixture's config includes it, and a mul-free fixture excludes mul/div. A test asserts this per fixture.
6. Padding: a table scan proves every non-live slot is MINUS_ONE in all fields and that no live row equals the padding row. Mid-instruction slots of RVC-expanded code are specifically checked.
7. `next_pc` correctness: every live row has `next_pc` = pc + (2 or 4), matching the original encoding's length. A test verifies this against the loader's halfword map.
8. Identity determinism: identity computed twice in one process and across two local process runs is byte-identical. A CI matrix job added this stage asserts cross-OS equality; committing the passing matrix config satisfies the gate, and the first matrix result is recorded in the handoff. Rebuilding the guest from source (S10 reproducibility) and recomputing also matches.
9. Identity sensitivity (tamper controls): flipping one instruction word in the image, changing `bytecode_size_words`, removing one family from the set, and changing one height each produce a different identity.
10. The print tool renders the decoded table for an arbitrary user-supplied ELF (not just fixtures), or fails with a named loader/decode error.

## Handoff
Freeze the `Instr` public shape and `decode`. Freeze `DecodedTables`: field set, per-family bitmasks, column export. Freeze `VmConfig` with its fields plus serialization. Freeze `ProgramIdentity`: contents, wire encoding, and the exact digest recipe. Freeze the `ProgramParams` defaults and the family list with its pc-claiming rules, including the system-instruction ownership rule that claims ECALL/EBREAK/FENCE pcs for the add/sub/lui/auipc family as a named system row kind. Freeze the append-only numeric FamilyId table in constants, in canonical ascending order. It gives a numeric id to every family: add/sub/lui/auipc, jump/branch/SLT, shift/bitwise, mul/div, mem word, mem subword, atomics, and init/teardown, with delegation ids appended later. Later transcript seeding and canonical ordering cite that table. Define the statement descriptor here, and as a `docs/GLOSSARY.md` note: it is the static VmConfig plus the per-proof per-family shard counts, absorbed as two adjacent typed messages. The static `VmConfig` excludes per-proof shard counts, and the two are adjacent typed absorbs. Record the measured fib table sizes and the first cross-OS CI matrix result.
